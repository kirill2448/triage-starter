# Тестовое Neowise. AI-помощник для входящих заявок

## Запуск и тесты

Нужен Node.js 20+. Зависимостей и ключей нет.

```sh
node server.mjs          # или: npm start  → http://127.0.0.1:3000 (порт: PORT=8080 node server.mjs)
node --test test/triage.test.mjs   # или: npm test
```

## Что сделано

- `triage.mjs` — логика без HTTP: проверка ввода (`parseRequestBody`), вызов модели с лимитом 300 мс (`AbortSignal` + `Promise.race`, лимит соблюдается, даже если модель игнорирует сигнал), строгая проверка ответа модели (`validateModelOutput`: JSON-объект, `topic` ∈ `delivery|pricing|other`, непустой `draft`). Наружу отдаются только `status/topic/draft`.
- `server.mjs` — `POST /api/triage`: битый JSON, не-объект, отсутствующий/нестроковый/пустой `text`, слишком большое тело → `400 {"status":"invalid_input"}`; таймаут, ошибка, неподходящий ответ модели → `200 {"status":"manual_review","topic":null,"draft":null}`. Сервер экспортирует `createServer()` для тестов; `node server.mjs` работает как раньше. `mock-ai.mjs` не менялся.
- `index.html` — тема и редактируемый черновик при успехе; при `manual_review` и сетевой ошибке — сообщение «разберите вручную», предыдущий черновик очищается в начале каждого запроса; пустой ввод отсекается до запроса; кнопка блокируется на время запроса, ответы на устаревшие запросы игнорируются.
- `test/triage.test.mjs` — 21 тест на `node:test`: успех, все виды некорректного ввода, все 5 меток сбоя имитатора, таймаут при «зависшей» модели, отмена сигнала, фильтрация лишних полей.

## Польза для менеджера

Менеджер не тратит время на сортировку и первый вариант ответа, а при сбое AI сразу видит, что заявку надо разобрать вручную, и не отправит клиенту устаревший или пустой черновик. Измерять: среднее время от получения заявки до ответа и доля черновиков, отправленных без правок (а также доля `manual_review`).

## Исходное задание

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

### Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

### Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
